# SystemVerilogLanguageServer

A [Language Server Protocol](https://microsoft.github.io/language-server-protocol/)
implementation for SystemVerilog. It speaks LSP over JSON-RPC on
`stdin`/`stdout`.

## Status

The following capabilities are implemented end-to-end:

| Method                          | Status | Notes |
|---------------------------------|--------|-------|
| `initialize` / `initialized` / `shutdown` / `exit` | ✅ | full LSP lifecycle |
| `textDocument/didOpen` / `didChange` / `didClose`  | ✅ | file state is kept in memory |
| `textDocument/definition`       | ✅ | resolves to the symbol's source range |
| `textDocument/references`       | ✅ | declaration + use sites (parser-backed) / declaration only (in-memory) |
| `textDocument/documentSymbol`   | ✅ | walks `Root.BuildingBlocks` and `Members` to produce a nested tree |
| `textDocument/hover`            | ✅ | markdown block generated by `HoverContent`; `IHoverContentProvider` extension point lets the editor add parser-side details |

Symbol lookups run against an `ISystemVerilogCore`. The default is
`InMemorySystemVerilogCore`, which retains only the text the client has
sent us; the `CodeEditor2VerilogPlugin` ships a parser-backed adapter
under `pluginVerilog.CoreBridge` that satisfies the same interface.
The architecture means the language server has no compile-time
dependency on the plugin or on Avalonia.

## Building

```
dotnet build SystemVerilogCore/SystemVerilogCore/SystemVerilogCore.csproj
dotnet build SystemVerilogLanguageServer/SystemVerilogLanguageServer/SystemVerilogLanguageServer.csproj
```

## Architecture

```
        client (editor)                  server process
        ──────────────                   ──────────────
   LSP request/notification  ──stdin/stdout──▶  LspStreamReader
                                                   │
                                                   ▼
                                            LspHandler (dispatch)
                                                   │
                                                   ▼
                                  InMemorySystemVerilogCore  (default)
                                                   │   ▲
                                                   │   │ adapter
                                                   ▼   │
                                  ISystemVerilogCore / ISystemVerilogProject
                                       (defined in SystemVerilogCore)
```

`SystemVerilogCore` only owns the interfaces. The language server
default implementation is `InMemorySystemVerilogCore`; the plugin
provides a parser-backed implementation (`VerilogSystemVerilogCore`)
that satisfies the same interfaces and is wired in by the editor.

## Hover output example

When the language server is wired to the parser-backed adapter, hovering
over a variable produces a markdown block of the form:

```markdown
```systemverilog
my_var  // type: UserDefinedVariable, width: 32
```

_Defined in: `/path/to/file.sv`_
```

For a module:

```markdown
```systemverilog
module my_module  // ports: clk, rst, data_in, data_out
```

_Defined in: `/path/to/my_module.sv`_
```

## Document symbol tree example

A `textDocument/documentSymbol` request returns a nested tree
rooted at `$root` (the synthetic file namespace):

```
$root  (Namespace)
  module top  (Module)
    Variable x  (Variable)
    Variable y  (Variable)
  package pkg  (Package)
    Constant MY_K  (Constant)
```

The `Kind` is mapped from `SystemVerilogNamedElementKind` to the
LSP-spec `SymbolKind`.

## Editor integration

### VS Code

The language server speaks the standard LSP on stdin/stdout. A minimal
client wrapper can be written in TypeScript using `vscode-languageserver`
or generated with `vscode-languageserver-node`. The configuration is
boilerplate:

```json
{
  "languageserver": {
    "SystemVerilog": {
      "command": "dotnet",
      "args": [
        "run",
        "--project",
        "<repo>/SystemVerilogLanguageServer/SystemVerilogLanguageServer/SystemVerilogLanguageServer.csproj"
      ],
      "filetypes": ["systemverilog", "verilog"]
    }
  }
}
```

### Neovim (nvim-lspconfig)

```lua
require'lspconfig'.systemverilog_lsp.setup{
  cmd = { 'dotnet', 'run', '--project',
    vim.fn.getcwd() .. '/SystemVerilogLanguageServer/SystemVerilogLanguageServer/SystemVerilogLanguageServer.csproj' },
  filetypes = { 'systemverilog', 'verilog' },
}
```

### Helix

```toml
[[language]]
name = "systemverilog"
language-servers = [ "systemverilog-lsp" ]

[language-server.systemverilog-lsp]
command = "dotnet"
args = ["run", "--project", "SystemVerilogLanguageServer/SystemVerilogLanguageServer/SystemVerilogLanguageServer.csproj"]
```
